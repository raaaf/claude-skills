## What this audit was about

The previous session had "fixed" the two PreToolUse guards of `/audit` by correcting their path.
This audit found the controls were still completely dead, for two further independent reasons, and
then found two more defects in the fix for those.

## Critical (all fixed and verified)

1. **[Security] audit/SKILL.md frontmatter** — the hooks were declared with a `hook:` key holding a
   shell string. The documented schema is nested: `hooks:` per event, a list of
   `{matcher, hooks: [{type: command, command}]}`. Claude Code rejected the entry and registered
   nothing. Reproduced, not argued: a debug run logged `Invalid hooks in skill 'audit'` with two Zod
   errors, while a control skill using the documented form logged `Registered 1 hooks from skill`.
   After the fix the error is gone from the log.
2. **[Security] both guard scripts** — the blocking path ended in `exit 1`. Per the hooks docs only
   exit 2 blocks a PreToolUse call; every other non-zero code is a non-blocking error and the tool
   call proceeds. `block-worktree-wide-git.sh` now exits 2. `block-unsafe-push.sh` instead emits the
   JSON `permissionDecision: ask` and exits 0, matching what its own message asks for and what the
   global hook in `settings.json` already does for the same case.

## Important (all fixed and verified)

3. **[Security] both guards, prefix matching** — the anchor accepted only start-of-line, `&&`, `;`
   and `|`. Verified by execution as reaching the guarded command unblocked: env-var prefix,
   subshell, brace group, `if/then`, `for/do`, leading `&`, absolute binary path.
4. **[Security] block-worktree-wide-git.sh, checkout rule** — only fired on a literal `--`, so
   `git checkout <pathspec>` passed although it silently discards uncommitted work.
5. **[Architecture] audit/SKILL.md** — the two hook entries duplicated the install-path probe. They
   could not simply be merged: each guard reads stdin, which is single-consumption, so the second
   would have received an empty pipe. Resolved by a new dispatcher, `audit/hooks/pretooluse-bash.sh`,
   which reads the payload once, feeds both guards the same string, aggregates the verdicts and
   locates its siblings via its own path, which also removes the duplicated probe.
6. **[Docs] write-a-skill/references/hooks-pitfalls.md** — the testing recipe written earlier the
   same day told the reader to expect `exit 1` as the block, contradicting line 33 of the same file.
   That file is what future skill hooks are written from.
7. **[Docs] README.md and CLAUDE.md** — both claimed all hooks live in `~/.claude/hooks/`. Git
   history shows `audit/hooks/` predates both claims by two months, so they were never accurate. The
   fix distinguishes global hooks (outside version control, wired in `settings.json`) from
   skill-scoped hooks (shipped in the skill, declared in its frontmatter) rather than deleting the
   rule.
8. **[Docs] README.md** (cross-reference pass) — said both guards are declared in the frontmatter.
   Only the dispatcher is; the guards are siblings it invokes.

## Minor (fixed)

- Case sensitivity let `GIT PUSH` through both guards. Not theoretical here: the boot volume is
  case-insensitive APFS and `GIT --version` resolves to the real binary, so the uppercase form would
  really execute.
- Backtick command substitution bypassed both guards after round 2 narrowed the anchor.
- `git stash list` and `git stash show` were blocked although read-only.
- Phase 1 had no check that the hook scripts exist. A partial install silently drops both controls.
  There is now a non-blocking warning per missing script; hard-failing would contradict the
  deliberate fail-open design.

## Minor (accepted, documented in the files)

- `grep` anchors per physical line, so a multi-line command whose second line merely mentions a
  destructive git phrase is blocked. The portable alternative would blur chain-operator boundaries
  and risk an under-block.
- A backtick inside a single-quoted argument cannot be told apart from a live one, so a commit
  message quoting a dangerous command as inline code is blocked. Both failures are over-blocks, never
  a missed destructive command, and both have a trivial workaround.
