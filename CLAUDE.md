# claude-skills

Repo of Claude Code skills. Each skill is a slash command implemented in Markdown + Bash, no runtime.

## Stack

- Markdown + YAML frontmatter (skill orchestrator)
- Bash for deterministic logic (`audit/bin/`, `~/.claude/hooks/`)
- Claude Code 2.1.218+ frontmatter features: `model`, `effort`, `allowed-tools`, `disallowed-tools`, `maxTurns`, `context: fork` + `agent` + `background`. Full field reference (verified against the official docs, August 2026): `docs/references/frontmatter.md`
- No dependencies — no npm, no composer, no venv

## Architecture

Each skill follows the same shape:

```
skill-name/
  SKILL.md              orchestrator (under 500 lines)
  agents/*.md           subagent definitions (one per worker)
  references/*.md       on-demand details (TOC if >100 lines)
  guidelines/*.md       content best practices loaded by workers
  bin/*.sh              deterministic helpers (audit only)
  evals/                fixture-based recall measurement (audit only)
```

Key invariants:

- **Orchestrator writes, subagents return.** Subagents cannot write under `.claude/` (hardcoded permission protection, also under `bypassPermissions`). Learning, suppression, log files: structured output → parsed by orchestrator → written by orchestrator.
- **Single source of truth.** `/full-audit` references `../audit/agents/` instead of duplicating. Same for `guidelines/`. Edit once.
- **Frontmatter `model: inherit`** on the orchestrator skills (audit, full-audit, design-audit, plan-it) since 2026-09-03: they run on the session model, the same reasoning `/delegate` documented earlier. `ship` pins `model: sonnet`. Never pinned versions; pin only on Bedrock/Vertex/Foundry.
- **Per-dimension pipeline (since 2026-09-05).** The old collapsed-worker routing (w1-code/2-security/w3-frontend/w4-content) is gone from `/audit` and `/full-audit`; `audit/agents/w3-frontend.md` still exists because `/design-audit` dispatches it as its visual worker, do not delete it. `audit/workflows/find.js` runs one Workflow `pipeline()` per dimension (13 unconditional, plus a conditional 14th, `payments`, gated on `detect-stripe.sh` reporting `STRIPE=yes` AND the diff touching the Stripe surface it found): scout → chunk (code) → specialists (parallel, `agentType` per dimension: `security-auditor` for security/privacy/payments, `performance-auditor` for performance, `ui-ux-reviewer` for a11y/ui_design/ux/typography/animation, `code-reviewer` for architecture/code_quality/seo/docs_sync/copy) → verifier → a per-Critical Opus refuter. `audit/workflows/fix.js` runs the fix wave the same way: one `audit-fix-agent` per file, `audit-fix-verifier` per 3-5 fixes, then a regression pass. Sonnet everywhere except the scout (`Explore`, sonnet) and the Critical refuter (opus). Haiku is never routed: a full-audit run showed a haiku code-quality batch producing 5 findings the validator discarded as impossible or hallucinated, while sonnet specialists in the same run produced zero — and a cheaper model's wrong finding still costs a verifier round and a fix wave, which erases the savings. Do not route a dimension to haiku without re-litigating that evidence.
- **Platform support.** `detect-framework.sh` emits `PLATFORM=web|native|cross` (laravel/nextjs/nuxt/django vs ios/android vs react-native/flutter). Native projects: the security specialist plus a11y/performance/ui_design/ux/typography (dimension modules 6/3/8/9/7) additionally read `guidelines/native-mobile.md`; Swift/Kotlin/Dart count as frontend files; `check-i18n-keys.sh` handles `.lproj` and `values-*/strings.xml`.

## Conventions

- **SKILL.md under 500 lines.** If approaching, split into `references/*.md` (one level deep, never nested).
- **Reference files >100 lines need a TOC** at top.
- **YAML `name` is lowercase + hyphens**, no `claude`/`anthropic`. Description in third person, includes both *what* and *when*.
- **Everything is written in English** (since 2026-07-08, full migration): SKILL.md bodies, agents, references, guidelines. German ONLY for: `when_to_use` trigger phrases (they mirror the user's prompt language), runtime user-facing strings inside bash blocks, and deliberate German example content (copywriting guideline).
- **Contract identifiers are never renamed casually.** `ALLE_DATEIEN`, `AKTUELLES_LOG`, `DATEISTRUKTUR` and `ZENTRALE_PATTERNS` are German-named cross-file contracts: learning/challenge agents receive the parameters by these exact names. Renaming needs a coordinated pass over every referencing file. Reviewers: these are NOT English-migration violations. **`RUNDE`, `MAX_RUNDEN`, `BEREITS_GEFIXT`, `{BATCH_DATEILISTE}` and the status line `SAUBER|FIXES_APPLIED|NO_CONVERGENCE | RUNDE n/m` lost their contract status on 2026-09-05**, and `ARCHITEKTUR-NOTIZ`, `{DATEILISTE}` (2026-09-15) and the worker reply sentinel `"Keine Findings."` (2026-09-16) were removed from this list because a repo-wide grep found them in no active skill or agent file: the per-dimension pipeline rebuild removed `/audit`'s round loop entirely, `audit-loop.sh` (which used to parse that status line) is now a permanent no-op, and the new terminal line is `Audit: {C} Critical, {I} Important offen | Push {frei|blockiert|nicht zutreffend}` (parsed by no hook).
- **No emojis. No em-dashes in new English prose where avoidable.**
- **Frontmatter for skills** sets `model: inherit` (or `sonnet` for the cheap ones), `effort: high|xhigh` for the four orchestrator skills and `medium` for `/ship` and `/delegate` (neither runs a specialist pipeline), `allowed-tools: [...]`, optional `hooks: { PreToolUse: ... }`.
- **A guideline that demands evidence names the worker role that produces it.** "Verify by running the suite", "measure the payload", "grep every call site" only holds if the role that reads the guideline has the tool for it; cross-check against the `tools:` grants in `~/.claude/agents/*.md` and the `agents/*.md` specs before writing such a rule (learning 2026-08-05).
- **Agent files here are orchestrator-dispatched worker specs, NOT Claude Code subagent definitions, and they have no frontmatter.** Every `<skill>/agents/*.md` in this repo opens with an `# Subagent N: Name` heading followed by a Markdown bullet list (`- **subagent_type:**`, `- **model:**`, `- **maxTurns:**`); the orchestrator reads those values and passes them to the Agent tool. A real Claude Code subagent definition is a different artifact: it lives in `.claude/agents/`, uses genuine YAML frontmatter, requires `name` + `description`, and has no `subagent_type` field at all (its `name` IS the type). Both forms are valid; only mixing them up silently produces a file nobody parses. Field set for the real form and the distinction: `docs/references/subagents.md`.
- **Finding output cap** is 50 words, only `file:line` refs, no code snippets. Enforced in `audit/agents/prompt-template.md`.
- **Skill-frontmatter hooks do not reach subagents.** Per the hooks docs ("Hook scope"), a `hooks:` block in `SKILL.md` applies to the main session's tool calls only; a subagent dispatched by the skill runs without it. The worktree-wide git guard therefore also lives in the `hooks:` frontmatter of every registered agent that has Bash (`~/.claude/agents/audit-fix-agent.md`, `audit-fix-verifier.md`, `spec-executor.md`), same dispatcher command as `audit/SKILL.md`. (`audit-content-worker.md`/`audit-triage.md` carried it too before the 2026-09-05 per-dimension rebuild deleted both — the collapsed workers and the opt-in LLM triage no longer exist.) Three stash incidents on 2026-08-27 happened with the skill hook "in place".
- **Hook safety:** never `claude` from inside a Stop/PreToolUse hook (would spawn an infinite loop). Two kinds of hooks: global hooks (`sync-skills.sh`, `audit-loop.sh`, `pre-compact.sh`, `auto-format.sh`) live in `~/.claude/hooks/`, which since 2026-09-03 is a symlink into the private repo (`claude-skills-personal/hooks/`, installed by its `bin/install-dotfiles.sh`), wired up in `~/.claude/settings.json` (also symlinked from that repo, secret-free). Skill-scoped hooks ship inside the skill directory (e.g. `audit/hooks/`), are version controlled; the skill's frontmatter registers one dispatcher (`pretooluse-bash.sh`) that invokes the guards (`block-worktree-wide-git.sh`, `block-unsafe-push.sh`) as siblings, aggregating their results.

## Registered subagents (`agents/`)

`agents/*.md` are the real Claude Code subagent definitions (YAML frontmatter, `name` = the `subagent_type`) that the skills dispatch: `audit-fix-agent`, `audit-fix-verifier`, `audit-learning-agent`, `plan-challenger`, `plan-learning-agent`, `spec-executor`, `design-surface-mapper`, `design-reference-verdict` (the last two since 2026-09-16; `/design-audit` dispatched them as bare `general-purpose` with inline briefings before), `screens-view-discoverer` (points at `screens/agents/view-discoverer.md`, `/screens` Phase 1/4), plus the generic `code-reviewer`, `security-auditor`, `performance-auditor`, `ui-ux-reviewer`, `test-writer`. `~/.claude/agents` is a symlink to this directory (see `claude-skills-personal/bin/install-dotfiles.sh`), so an edit here is live immediately and versioned. Each definition only points at the worker spec inside the skill (`audit/agents/fix-agent.md` etc.); the procedure stays in the skill. The three agents with Bash carry the worktree-wide git guard in their own `hooks:` frontmatter. (`audit-triage` and `audit-content-worker` were deleted 2026-09-05: the per-dimension rebuild removed the opt-in LLM triage and the collapsed content worker.)

## Effort levels (set on skill frontmatter or via `CLAUDE_EFFORT`)

Since the 2026-09-05 per-dimension rebuild, `/audit` and `/full-audit` no longer scale by rounds —
one `find.js` pass covers every selected dimension, one `fix.js` pass fixes every finding it
confirms, including Minor, or discards it with a reason (decided 2026-09-25). `CLAUDE_EFFORT` no
longer preselects a fix scope: the only remaining fix-scope value is `AUDIT_FIX_SCOPE=none`
(headless find & log only), set explicitly, never derived from effort. `/plan-it` is unaffected by
this rebuild:

| Level | /plan-it (default `high`) | /design-audit (default `high`) |
|---|---|---|
| low | 3 challenges, no eval, no learning | elevation cap 3, fixes not verified |
| medium | 4 challenges, no eval | elevation cap 5, fixes verified |
| high / xhigh (default) | 5 challenges, full eval | elevation cap 7, fixes verified |

`/audit`, `/full-audit`, `/plan-it` and `/design-audit` all carry `effort: high` in their frontmatter, and per the dual-use rule that value is what `${CLAUDE_EFFORT}` receives; the `:-high` fallback in `/design-audit` Phase 0 only matters if the frontmatter line is removed. `/design-audit` additionally scales `MAX_ELEVATION` and `VERIFY_FIXES` (`design-audit/SKILL.md` Phase 0), a different knob unrelated to fixing (`/design-audit`'s fix wave is unconditional since 2026-09-25, see the Skill roster).

Issue policy: GitHub issues only for decision points the user explicitly defers (fix now / defer / dismiss prompt at audit end). Minor findings never become issues; unconfirmed low-confidence findings are verified or dropped, never tracked. At audit start (Phase 0, second check), open `audit-finding` issues are offered for fixing in the same run (closed via `gh issue close` after a verified fix); open PRs are collected as dedup context — no issue is created for something an open PR already addresses.

## Project-specific overrides

Projects can override globals by adding files to their own `.claude/`:

- `.claude/audit-guidelines.md` — read in `audit` Phase 1, takes precedence over global `guidelines/*.md`. May also declare a `perf-measure: <cmd>` line to enable verify-by-measurement for performance fixes (see Gotchas), or a `scope-extensions: <ext> [<ext> ...]` line to add extensions to `/full-audit`'s source scope (see Gotchas) — this repo's own `.claude/audit-guidelines.md` sets `scope-extensions: md` so `/full-audit` covers the SKILL.md/agents/guidelines orchestrators
- `.claude/plan-guidelines.md` — read in `plan-it` Phase 0.7, threaded to all challenge agents
- `.claude/ship.md` — `/ship`'s per-project config, created by `/ship` when absent: `deploy-command:` (asked before every run), `test-command:` (also read by `/audit` Phase 3 for the fix-wave baseline), `health-check:`. All three parsed by `orch_ship_value` in `lib-orchestrator.sh`; a repo-supplied command surface, see the Gotcha on the three sites that run one
- `.claude/stripe-golive.md` — on a Stripe repo only: the go-live points that can only be answered in the Stripe dashboard, not in code (tax, receipt mails, webhook alerting, ...). Written as a template by the `payments` dimension on its first run, answered by the user; an `OFFEN` line surfaces as one Minor finding, and `/full-audit` Phase 0 reads the file to decide whether payments needs a re-run
- `.claude/audits/learning-log.md` — auto-generated per-project audit history
- `.claude/audits/suppressions.json` — auto-generated dismissed-finding list
- `.claude/plans/logs/*.md` — auto-generated per-plan logs

## Gotchas

- **Per-file guideline selection (`applies_to` + `priority`).** A guideline may declare `applies_to: <ERE>` (matched against the diff's changed file paths) and `priority: non_negotiable|mandatory|recommended` in YAML frontmatter. `match-guidelines.sh` (SKILL.md Phase 1) emits which guidelines match the diff; workers load only the listed ones (prompt-template.md "Guideline-Scope" rule) and use `priority` as a severity anchor (non_negotiable→Critical, mandatory→Important, recommended→Minor). **Backward compatible:** a guideline without `applies_to` is always applicable, so migration is incremental and never silently drops a guideline. Migrated so far: `accessibility`, `accessibility-2026`, `atomic-design`, `color`, `data-migrations`, `docs-sync`, `flow-completeness`, `native-mobile`, `seo`, `typography`, `ui-animation`, `ui-ux-patterns`, `ui-visual-design`; project-level (`theme-fork`) and global (`security`, `code-quality`, `performance`, `architecture`, `documentation`, `copywriting`) stay always-on. Concept borrowed from mcp-context-toolkit (`query_rules_for_file`); single ERE per file, no YAML-list parser. bash 3.2 safe.

- **`SOURCE_DIRS` from `detect-framework.sh` is quoted per-element, not as a whole string — a different `%q` convention from `perf-measure.sh`, don't conflate them.** `detect-framework.sh` emits three lines (`FRAMEWORK=`, `SOURCE_DIRS=`, `PLATFORM=`); `SOURCE_DIRS` is a list of directories, each individually `%q`-quoted, joined by plain unescaped spaces. A `%q` escape only ever protects a space that is actually inside a directory name, so the separators between directories stay real spaces and the value round-trips through `eval "SOURCE_DIRS_ARR=($SOURCE_DIRS)"` (bash's `NAME=(...)` compound-assignment syntax) into an array with one directory per element, spaces-inside-names included. This replaced an earlier version that applied `%q` to the whole joined string, which escaped every separator too and made "which space is a separator" undecidable after the fact — the workaround at the time was to skip any top-level directory whose name contained a space, trading corrupt scope for silently narrower scope; both are gone now. Consumers must never run the raw 3-line output through one blanket `eval "$(...)"`: the `SOURCE_DIRS` line's unescaped separators parse as multiple shell words, not a single assignment. Capture the stdout as text, extract each value by key, then reconstruct the array with the targeted `eval` above (pattern in `full-audit/references/scope.md` and `audit/SKILL.md` Phase 1). Directory names are attacker-controllable in an audited repo, which is why the `eval` form matters, not just convenience: the safety comes ENTIRELY from `detect-framework.sh`'s per-element `printf %q` — an unescaped `$(...)` inside an `eval "arr=(...)"` executes like anywhere else in `eval`, and `%q` is what turns it into a literal word (verified 2026-09-16). Single-line contract has one honest limit: a directory name containing a literal newline cannot round-trip (undocumented elsewhere, don't try to "fix" this without changing the whole contract to NUL-delimited). This is a distinct mechanism from `perf-measure.sh --detect`'s whole-string `%q` (see below) — that one quotes an entire command for a single assignment, on purpose, because a shell command genuinely is one value; `SOURCE_DIRS` is a list, and needed per-element quoting instead. Don't "harmonize" the two.

- **The audit pipeline is find → verify finding → fix → verify fix.** Four stages, and the two verification stages do different jobs: D.5 is mechanical (does the file exist, is the line in range), D.7 is semantic (is the problem actually there), the fix-verifier judges the applied fix. Same class as `ship`'s test gate and deliberately as un-gated: a test suite is not production, the command is the one the repo's own developers run, and a hostile `test-command:` already reaches `/ship`. Listed here so the count stays right. The fourth: `.screens/config.json`'s start/stop/seed/migrate command fields (`/screens` "Trust boundary"). `state.json` stores the sha256 of every confirmed command field; when the current hash differs (config edited, repo cloned fresh), `screens.mjs trust` reports `NEEDS_CONFIRM` and the skill shows the commands and asks once before running them, since `migrate:fresh` is destructive, unlike a test command. `audit/bin/perf-measure.sh` reads `perf-measure:` from `.claude/audit-guidelines.md`, and `ship/SKILL.md` reads `test-command:` (Phase 2b) and `deploy-command:` (Phase 4) from the audited repo's own `.claude/ship.md` — same trust-boundary class, opening a hostile or compromised repo and running either skill executes its commands. `ship` was missing from this list until the 2026-08-11 full-audit flagged it (open point 9); documented here now because it is also the one of the two that reaches production. The other stays un-gated by design: worst case is a wasted measurement, cheap to notice and already fails loud on its own. `ship/SKILL.md` Phase 4 now puts an `AskUserQuestion` in front of `DEPLOY_COMMAND` on every run, even on the golden path where the rest of the pipeline runs silently once the audit/test gates are green — because `DEPLOY_COMMAND` is resolved once at Phase 0 and then reused silently on every later run, so a `.claude/ship.md` edited (by a teammate, or by an attacker with repo write access) between two `/ship` runs would otherwise execute with zero visibility before hitting prod. Push and the test gate stay silent-on-green on purpose; deploy is the one step in the pipeline that is both irreversible and production-facing, so it is the one that gets a checkpoint even when nothing is wrong.
- **`cache-write.sh` and `patterns-store.sh` mutate the audited repo's `.gitignore`, on purpose, but narrower than before.** Both write `.claude/audits/{cache,patterns}.json` and used to unconditionally append a `.gitignore` line behind a literal `grep -qF` check, which fired even when a broader existing rule already covered the path (redundant append) and even when the file was already tracked (a `.gitignore` line has zero effect on a tracked file, but the append made it look like the tool had fixed something). Both scripts (2026-08-11) now check `git check-ignore` first (already covered → skip) and `git ls-files --error-unmatch` first (already tracked → skip and warn instead, since `.gitignore` cannot un-track it), and print a stdout line whenever they do append or warn, so the mutation is visible in the audit log instead of being a silent side effect on a file the audit run does not own. Removing the behaviour entirely was considered and rejected: `cache.json`/`patterns.json` are genuinely disposable, project-local audit state, exactly the class of file `.gitignore` exists for, and the run most likely to accidentally commit them is the very first audit against a repo that has no `.claude/audits/` convention yet.
- **The run ledger (`$HOME/.local/state/claude/skill-runs.jsonl`) records how a run actually went, deliberately outside any repo and outside `~/.claude`.** `run-log.sh` appends one line per terminal outcome from the six skills that change code or ship it (`/audit`, `/full-audit`, `/plan-it`, `/design-audit`, `/delegate`, `/ship`) and never fails the calling skill (any internal error exits 0 silently). It lives outside any project because each line carries a project path, branch name and commit SHA that are personal to this machine, and `claude-skills` itself is a public repo. It moved out of `$HOME/.claude/` on 2026-08-26 because the Bash sandbox treats that directory as a protected path and denies writes to it with no way to opt out, so a ledger there would have stopped recording silently the moment sandboxing went on. It exists because before 2026-08-12 nothing recorded this at all: `/ship` had gone untriggered for a stretch (its `when_to_use` was English-only), the eval harness under-reported recall for months, and a learning backlog grew across two retros with no action — none of it visible from any artifact. The check is read inline, not from a dashboard: `audit/references/learning-phase.md` runs `run-stats.sh` at the point every `/audit` and `/full-audit` run already passes through (the learning phase, `full-audit/SKILL.md` referencing the same step rather than duplicating it) and surfaces any `RUNSTAT` anomaly in the audit log's `## Open Points` under the same `AGED` escalation recurring open points already use. The thresholds started as an admitted first guess, and two scheduled calibration checks (2026-08-19, 2026-08-26) settled them against 45 real runs under the rule that a condition firing repeatedly without ever leading to an action is itself a defect and gets deleted, not silenced. Three of the original five conditions are gone: `zero-findings-streak` (0 fires; no run in the ledger has ever reported zero findings, so it could not fire by construction), `never-triggered` (fired 9x every run, always for skills carrying no `run-log.sh` call at all; its one real signal, `/ship` silent for months, closed when the German trigger phrases added on 2026-08-11 made `/ship` fire on 08-21 and 08-22), and `duration-outlier` (0 fires; `--start` fires per session rather than per run in `delegate`/`plan-it`, so only 24 of 45 rows carried a duration and the median was structurally blind). Two remain: `gate-never-blocked`, now requiring 10 gated runs before "never blocked" is an observation rather than a small sample, and `ledger-stale`, the only condition that produced a finding both weeks — its message no longer asserts broken logging, because both times the real cause was commits landing without an audit run. Do not re-add a deleted condition without new evidence; the calibration checks are over and were not rescheduled.

## Adding a new skill

Follow this minimum:

1. Create `new-skill/SKILL.md` with frontmatter (`name`, `description`, `model`, `effort`, `allowed-tools`).
2. Add `agents/` for any subagents you dispatch.
3. Add `references/` for content over 100 lines.
4. Add `guidelines/` for opinionated best practices the agents should follow.
5. Run `bash ~/.claude/hooks/sync-skills.sh` to deploy locally.
6. Update root `README.md` to list the new skill.

## Adding a 2026 best-practice section to an existing guideline

Edit `audit/guidelines/{name}.md`. Append a new Roman-numeral section (e.g. `## XVI. New Topic (2026)`). Keep the file under 500 lines — if it would go over, split into a continuation file (`{name}-2026.md`, see `code-quality-2026.md`) and reference both in the worker's agent file. Don't rewrite existing content — additive only unless something is genuinely wrong.

## Audit Context

- Markdown + Bash skills repo, no runtime, no dependencies. Findings about missing package manifests, test frameworks, or CI configs for the skills themselves are noise.
- **Public repo on GitHub.** Secrets/keys/tokens anywhere in the diff are always Critical. Audit logs under `.claude/audits/` are committed (only `cache.json`, `full-audit-state.md`, `full-audit-batches/` and `.claude/plans/logs/` are gitignored), so they reference `file:line` and never reproduce file content. That rule is what makes committing them safe, not an optional style preference.
- `audit/bin/*.sh` and every hook must stay **bash 3.2 compatible** (macOS default): no `declare -A`, no `readarray`, no `${var,,}`. Exception: `audit/evals/run-evals.sh` (dev-only, requires bash 4+).
- German-named contract identifiers (`ALLE_DATEIEN`, `AKTUELLES_LOG`, `DATEISTRUKTUR`, ...) are deliberate cross-file contracts, NOT English-migration violations (see Conventions). `RUNDE`/`SAUBER`/`BEREITS_GEFIXT` lost contract status on 2026-09-05, see Conventions.
- Eval fixtures under `audit/evals/fixtures/` deliberately contain bugs, vulnerabilities, and anti-patterns — they are test data, never findings. Same for `evals/expected/*.json`.
- Skill bodies/agents/references/guidelines are English; German appears only in `when_to_use` triggers, runtime user-facing strings, and personal skills.
- Deliberate decision: orchestrator writes, subagents return (subagents cannot write under `.claude/`); `exit 2` blocking in the audit Stop hook is intentional, `additionalContext` would not block.

## Release process

There isn't one. Push to `main`, Stop hook syncs to `~/.claude/skills/`, next Claude Code session picks up the changes.
