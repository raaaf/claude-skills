# /full-audit internals

`/full-audit` runs the same per-dimension `audit/workflows/find.js`/`fix.js` pipeline as `/audit`
(see `audit/CLAUDE.md`), with `SCOPE=repo` and no push marker. It shares `audit/bin/` tooling
(`check-outdated.sh`, `run-cost.sh`, `check-ci-hardening.sh`, `match-guidelines.sh`,
`lib-orchestrator.sh`, `run-stats.sh`) rather than duplicating it.

## Gotchas

- **`/full-audit`'s source scope is a fixed extension list; `scope-extensions:` is the project-level, ADD-only escape hatch.** `full-audit/references/scope.md` walks `SOURCE_DIRS` for a hardcoded glob (`.php`, `.ts`, `.py`, `.sh`, …; `.md` only under `prompts/`/`prompt/`) — correct for most projects, where Markdown is documentation and staleness is docs_sync's job, not source scope's. A project whose Markdown genuinely IS the executable source (this repo's own `SKILL.md`/`agents/*.md`/`guidelines/*.md`, which an LLM follows literally) declares `scope-extensions: md` in `.claude/audit-guidelines.md`, same file and declared-line convention as `perf-measure:`. ADD-only, no REPLACE/SUBTRACT: it can only widen the fixed glob, so an absent or malformed line is always a no-op, never a narrowing. Sanitization accepts bare alnum tokens only (max 5) — a token like `*` that would "match everything" is rejected before it reaches `find`, not caught downstream. `.claude/audits/` and `.claude/plans/logs/` (this skill's own generated logs, in any project) are pruned unconditionally so enabling `.md` scope doesn't sweep in audit history as source. The exclude list needs both a `*/dir/*` and a bare `dir/*` form for every prune — when a directory is itself one of `SOURCE_DIRS` (true for `.claude/` in this repo), find's path has no leading `/` for the `*/`-prefixed form to match, and the unquoted `$EXCLUDE` expansion means an unmatched literal like `.claude/audits/*` is a live glob: bash pathname-expands it against real files before `find` ever sees it, corrupting the whole expression. `set -f` at the top of `scope.md`'s Phase 0 block turns that off for the rest of the script. `/audit` needs no equivalent: its scope is diff-based (`audit/bin/collect-scope.sh` lists whatever changed, any extension), so a changed `SKILL.md` is already in scope there today.
- **`/full-audit` runs the same per-dimension `find.js`/`fix.js` pipeline as `/audit`, with `SCOPE=repo` and no push marker (since 2026-09-05).** There is no more batch matrix, no `full-audit-state.md`, no `FULL_AUDIT_STATUS` line, and no `resume-check.sh`/`status-line.sh` (both deleted). Session-limit resume goes through the Workflow tool's own `resumeFromRunId`, not a hand-rolled state file — the `runId` lives in the audit-log header (`audit/SKILL.md` Phase 2/3).
- **In-progress marker is run-scoped, not wave-scoped, since the 2026-09-05 rebuild.** `/tmp/claude-audit-in-progress-{cwd-hash}` is claimed once before `find.js` starts, touched again after the find and fix Notifications (45-minute staleness), and released once at the end of Phase 4 — there is no more round loop to claim/release per round. `/design-audit` follows the same convention (see `design-audit/CLAUDE.md`).
