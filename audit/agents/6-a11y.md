# Dimension: Accessibility (WCAG)

## Look for

WCAG 2.1 AA compliance for all frontend views: semantic HTML, ARIA, forms, keyboard navigation,
contrast, touch targets. Read `guidelines/accessibility.md` and `guidelines/accessibility-2026.md`
in full. Native apps (`FRAMEWORK` = ios/android/react-native/flutter): use
`guidelines/native-mobile.md` section I instead — accessibilityLabel/contentDescription, Dynamic
Type, touch targets 44pt/48dp, VoiceOver/TalkBack groups, reduced motion. WCAG/ARIA HTML rules do
not apply there.

**Verify-before-flag (dominant false-positive source):**
1. Missing `aria-label` — first check for visible text, `<title>`, `aria-labelledby`, or an
   associated `<label>`. Not a finding if one exists.
2. Label association — `for`/`id` or a wrapping `<label>` can sit several lines away; read the
   whole block.
3. `x-show`/`display:none` visibility — check whether the element is even reachable visible.
4. Tailwind classes assembled via `@class([...])`, ternaries, or concatenation — trace the
   compiled value, not just the static attribute.

Still uncertain after checking → do not flag, or flag `confidence: low` naming what remained
unchecked.

**Widget checklist (mandatory for any finding on a custom widget** `role="radiogroup"`,
`tablist"`, `"listbox"`, `"menu"`, `"slider"` or similar): keyboard operability (arrow keys,
Home/End, Space/Enter), roving tabindex (exactly one `tabindex="0"`), dynamic ARIA states
(`aria-checked`/`aria-selected`/`aria-expanded`). Check the whole widget once you flag anything on
it, not just the flagged property.

**Custom accessibility actions per element:** >= 8 `.accessibilityAction`/custom actions on one
element (including inherited ones) is `Important` (VoiceOver rotor overload) — cite the count.

Skip when no frontend files are in scope.

## Severity

Severity is bound to a named WCAG-AA success criterion. `Critical` = a WCAG-AA violation that
blocks a whole interaction path for assistive-tech users (unusable widget, unreachable content).
`Important` = a WCAG-AA violation with a workaround. AAA criteria are never `Important`, at most
`Minor`.

## Output

Reply with the specialist schema: `findings[{id, severity, confidence, files, issue, impact}]`
plus `coverage`. Every ID is prefixed `a11y-`. Set `coverage` to `COVERAGE: full` or
`COVERAGE: partial | not read: {file1}, {file2}`.
